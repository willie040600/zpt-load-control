# 宅配通 車趟裝載控制塔(示意版)

以 3D 地圖呈現集貨、轉運、繼送的逐車趟裝載率,並把第 0 步的低裝載歸因與建議動作放進同一個畫面。

## 兩種視角
- **轉運中心視角(預設)**:北轉、桃轉、中轉、高轉四座轉運中心的等角 3D 畫面。南面為發車碼頭、東面為進站碼頭,車趟依真實發車與抵達時間進出,碼頭內側的籠車堆會隨裝卸增減;碼頭全滿時車輛在臨時車位排隊,碼頭空出後再進去。右側面板可採納建議、回填原因代碼,KPI 即時重算。
- **全台網路視角**:原本的台灣地圖,看站所與轉運中心之間的所有路線。

碼頭分配、裝貨 45 分鐘、卸貨 40 分鐘皆為示意(資料沒有碼頭紀錄)。3D 畫面顯示所有實際發車或到著為該中心的車趟,不論由哪個中心結帳;KPI 則依「結帳單位」計算,各中心加總不重複。資料沒有桃轉這個結帳單位,結帳在北轉且發車或到著為桃轉的車趟 KPI 歸桃轉,北轉與桃轉之間的對開車 KPI 算在發車端。

## 資料
- 來源:115 年 6 月、7 月(1–20 日)車趟派遣原始數據,共 9,748 趟(以派車單號去重)。
- `src/data/trips.json`:每趟車的裝載率、費用、歸因代碼與建議動作。不含司機姓名與車牌。
- 空載成本 = 車次費用 ×(1 − 裝載率),只計裝載率 <80% 的車趟。可省金額依同路線中位價估算,非正式會計口徑。
- 站所座標依運費表地址推估,僅供示意;金門為了畫面集中往東移。

## 建議動作分級
- 已驗證(可立即執行):35 噸載 ≤14 籠且同線常用 17 噸並較便宜 → 改派 17 噸;同站同日時差 ≤30 分 → 合併;跨站同方向時差 ≤30 分 → 共車。
- 時窗調整池:時差 30–120 分,需先把發車時間壓到 30 分內。

## 指令
- `npm install`
- `npm run dev`:開發伺服器
- `npm run build`:型別檢查並輸出單一檔案 `dist/index.html`(可直接用瀏覽器開啟)

## 更新資料(analysis/)
從原始 Excel 重新產生 `src/data/trips.json`:
1. 把 6 月、7 月的「車趟派遣SOP原始數據.xlsx」放到 `analysis/data/jun.xlsx`、`analysis/data/jul.xlsx`。
2. 執行 `sh analysis/run_all.sh`(需要 Python 3、pandas、openpyxl)。
3. 再執行 `npm run build`。

各腳本:`prepare.py` 轉檔 → `step0.py` 低裝載歸因 → `mismatch.py` 車型錯配分級 → `export.py` 產生建議動作與 JSON。
